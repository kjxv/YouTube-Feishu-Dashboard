# 飞书配置中心使用说明

## 一、关键字段怎么识别

飞书列名保持原样，避免程序因为列名变化而无法读取。程序关键字段会在字段说明中显示：

`【关键字段｜请勿删除或改名】`

这些字段可以按说明修改“值”，但不要删除字段、修改字段名或改变字段类型。没有这个标记的中文名称、翻译、用途和备注列主要用于阅读，不影响程序识别。

- `API字段字典`：标准字段ID、API来源、官方字段、数据类型、数据层级、查询组、当前可用状态、启用。
- `模块字段需求与映射`：模块ID、目标表ID、飞书列名、标准字段ID、启用。
- `数据项目配置`：配置键、配置值、启用。
- `账号非敏感配置`：配置键、配置值、启用。

## 二、为什么仍然保留英文 ID

`latest_video_tracker`、`VIDEO_VIEWS_PUBLIC`、`latest_tracking_days` 等内容是程序使用的稳定编号。它们不会随飞书列名或中文叫法变化，因此不能随意改名。配置表同时提供中文名称、用途和来源说明，日常阅读与调整优先看中文列。

API字段字典的 `当前可用状态` 只使用三种中文结果：

- `可直接使用`：底层获取或计算及主程序接入均已完成，可以建立并启用写入映射。
- `底层已实现，待接入主程序`：数据来源或计算能力已经具备，但当前模块还不能直接写入。
- `底层未实现`：尚未完成可靠的数据获取或计算能力，不能启用写入映射。

旧表中的 `实现状态` 列和“已实现、已接入、待实现”等旧值仍可被程序读取，但新建表和后续同步统一使用上述名称。第9步会阻止任何状态不是“可直接使用”的启用映射。

## 三、模块字段需求与映射

- `映射名称`：中文主字段，例如“视频实时快照表｜累计播放量”。
- `模块ID`：程序模块编号，一般不要修改。
- `模块中文名`：功能板块的中文名称。
- `目标表中文名`、`目标表ID`：说明数据写入哪张飞书业务表。
- `飞书列名`：必须和目标业务表中的列名逐字一致。
- `标准字段ID`：系统内部统一字段编号，一般不要修改。
- `标准字段中文名`：标准字段的中文解释。
- `API类型`、`API官方字段`：说明数据来自哪个 API；系统计算值会明确写为“非API”。
- `写入方式`、`实现状态`：便于阅读的辅助说明；能否启用以 API字段字典中的 `当前可用状态` 为准。
- `启用`：取消勾选后，远端配置加载时不再把该字段交给当前模块写入。

当前最新视频模块使用三表复合映射。三张表的真实列名需要在第9步核对；未来新增字段只有在字典状态为“可直接使用”后才能勾选映射表的 `启用`。

## 四、数据项目配置

这张表控制“系统如何运行”。日常只修改 `配置值` 或 `启用`，不要修改 `配置键`。

- `latest_interval_minutes`：系统整点检查间隔，当前固定为 60 分钟。
- `latest_hourly_tracking_hours`：视频发布后按小时追踪的时长，当前为 72 小时。
- `latest_daily_collection_hour`：小时级阶段结束后的每日采集整点，当前为北京时间 8 点。
- `latest_analytics_interval_hours`：手动运行时的 Analytics 缓存保护间隔；自动任务按每天 8 点刷新。
- `latest_reporting_interval_hours`：Reporting 新报表检查间隔，当前为 6 小时。
- `latest_tracking_days`：最长追踪时长，当前为 28 天，并保留 7、14、28 天节点。

目标方案中的30分钟、1小时、3小时分阶段周期尚未接入；接入后会增加独立的中文配置项。当前直接把固定间隔改成60或180，只会让整个窗口统一变慢，不会自动形成分阶段周期。

## 五、账号非敏感配置

这张表控制“采集哪个公开对象、写到哪张业务表”。日常只修改 `配置值` 或 `启用`，不要修改 `配置键`。

- `youtube_channel_id`：YouTube频道ID。留空时由OAuth授权账号自动识别。
- `latest_video_main_table_id`：视频追踪主表ID。
- `latest_video_snapshot_table_id`：视频实时快照表ID，当前已接入。
- `latest_video_comparison_table_id`：视频同期对比表ID。

App Secret、OAuth Token、Google客户端密钥和数据库密码绝不能写入这张表，只能保存在 `.env` 或 `secrets/`。

## 六、配置何时生效

调度任务每次启动时读取飞书配置中心。读取成功后会保存最近一次有效配置缓存；临时无法访问飞书时，可在缓存有效期内继续使用最近一次有效配置。字段类型冲突或必需配置缺失时，系统停止并报告，不会猜测或伪造配置。

## 七、第一次真实同步前怎么检查

1. `yfd scheduler run-once latest_video_tracker --dry-run`：只检查 API 请求规划，不联网；下划线和连字符写法都兼容。
2. `yfd modules preview latest_video_tracker`：只读取 YouTube 最新视频，不写飞书和业务数据库。
3. `yfd modules validate-sync latest_video_tracker`：只读取飞书配置和三张业务表结构，不修改飞书。
4. 只有第三步报告的 `safe_to_run_full_three_table_sync` 为 `true`，才表示三表完整同步具备执行条件。

校验报告中：

- `configuration_ready` 表示该表的 Table ID、启用映射和实际列名相互一致。
- `implemented` 表示程序已经有该表的写入逻辑。
- `current_snapshot_sync_ready` 只代表现有快照写入链是否可用。
- `safe_to_run_full_three_table_sync` 才代表主表、快照表、同期对比表全部准备完成。

日常应该点击哪个入口、怎样调整字段和新增模块，见 [日常使用与扩展指南](日常使用与扩展指南.md)。
