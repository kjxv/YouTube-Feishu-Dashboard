# 模块开发规范

## 必须遵守

1. 每个模块有稳定英文 `module_id`、清晰版本和中文说明。
2. 模块只依赖公共 Protocol/Service，不直接构造 Google/飞书 SDK、数据库 Engine 或日志处理器。
3. 模块声明所需标准字段 ID；字段是否存在由版本化能力目录校验，业务列名由飞书映射决定。
4. 所有持久化通过公共 Repository/Storage；不得创建模块私有数据库。
5. 调度任务必须幂等，具有稳定 `task_id`、锁名、间隔、重试策略和可序列化游标。
6. 记录数据时使用 API 响应对应的真实观测时间。实时断档只记录事实，不插值、不补造。
7. 飞书行数管理统一调用 `ArchiveService`，模块只提供业务表标识和归档条件。
8. 新模块必须提供无真实凭证的单元测试；联网测试标记为可选集成测试。

## 推荐结构

```text
04_功能模块/NN_中文模块名/
  README.md                         面向维护者的中文边界说明
  src/yfd_example_module/           稳定英文 Python 包名
    __init__.py
    manifest.py                     模块信息与字段需求
    service.py                      业务编排
    task.py                         ScheduledTask 适配
    schemas.py                      模块内部值对象（需要时）
```

跨模块复用的代码不放进任何一个业务模块，应提升到 `03_公共核心框架/src/youtube_feishu_dashboard/` 中对应的公共接口或服务。

## 任务结果

任务返回结构化结果：状态、开始/结束时间、处理数量、写入数量、跳过数量、下一游标和非敏感诊断信息。异常由公共调度器分类、重试并写入任务运行记录。

## 合并检查

- `ruff check .`
- `mypy`
- `pytest`
- `yfd doctor`
- `git status --short` 中不应出现 `.env`、Token、OAuth 客户端、数据库或日志
