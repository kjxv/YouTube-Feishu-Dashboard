# 自动定时采集说明

## 一、现在采用的规则

Windows 每个整点唤醒程序一次。唤醒不等于一定请求 API；程序会按每个视频自己的发布时间和最后一次真实采集记录判断。

- 每轮先读取频道上传列表，筛选最近 28 天内已经公开的长视频；新视频公开后会在下一次整点自动纳入。
- 只把发布时间最新的一期标记为 `当前追踪视频=是`；窗口内其他视频仍是“追踪中”，但当前标记为“否”。
- 视频主表按视频 ID 保证一视频一行；发现历史重复主记录时自动保留一条并清理多余记录。
- Data API：发布后前 72 小时，每个北京时间整点最多采集一次。
- Data API：超过 72 小时后，到第 28 天为止，每天北京时间 08:00 采集一次。
- Data API：在发布满 7、14、28 天的实际时刻增加节点采集。视频通常在 20:00 发布，因此节点通常也是 20:00。
- Analytics API：每天北京时间 08:00 刷新一次。
- Reporting API：每天 02:00、08:00、14:00、20:00 检查新日报。报表本身仍由 YouTube 按天生成，多检查不会把日报变成小时数据。
- 第 28 天最终采集完成后停止例行追踪。

电脑关机或休眠时不会采集，也不会伪造缺失的小时记录。电脑恢复后，第一次整点检查会做一次当前真实采集；如果错过第 28 天最终节点，会在恢复后补一条真实最终记录。

## 二、Windows 使用方法

双击 `01_启动脚本/Windows/10.自动定时任务管理.bat`，可以：

1. 安装或更新当前电脑的定时任务；
2. 查看上次结果和下次运行时间；
3. 暂停或恢复；
4. 立即按定时规则检查一次；
5. 查看完整诊断；
6. 结束当前卡住的运行实例；
7. 从当前电脑卸载。

第 6 步仍是“强制立即采集”，不受是否到达整点或是否已经采集过的限制。管理工具中的“立即检查”则会遵守自动定时规则，两者用途不同。

运行日志位于 `runtime/logs/windows-scheduler.log`。也可以直接双击
`16.诊断定时任务.bat`，一次查看任务状态、仍在运行的 Python 进程、本地任务/锁/心跳以及
日志末尾。任务计划程序中的 `0x41301` 表示“任务仍在运行”，不是成功；如果持续很久，后续
整点会因禁止重叠而被跳过。可在第 10 个入口选择“结束当前卡住的运行实例”；重新安装或更新
任务后，单轮最长运行时间为 45 分钟。

## 三、飞书运行状态表

运行 `14.运行电脑升级并验收.bat` 会幂等创建一张独立的“系统运行状态”表，并把 Table ID
写入本机 `.env`。表中只有一条“统一调度器”记录，不占用视频或频道业务表：

- `最近调度唤醒时间（北京时间）`：系统任务是否真的启动了程序；
- `最近调度完成时间（北京时间）`：本轮是否正常退出；
- `最近状态`：运行中、正常、有失败或异常；
- `本轮到期任务数`：本轮真正执行了多少业务任务；0 也可能是完全正常；
- `本轮失败任务数`、`最近结果摘要`：快速判断失败模块和结果；
- `本轮飞书写入记录数`：两个业务模块实际新增或更新了多少条飞书记录；
- `最近一次调度结果`：直接显示整点、调度结果、最新视频 Data API 是否采集以及业务表写入数；
- `运行实例`、`程序版本`：确认究竟是哪台机器、哪个版本在运行。

每次统一调度唤醒都会更新这条记录，即使 YouTube 数据尚未变化、当轮没有业务任务到期，
也会留下可观察的完成时间。若长时间停留在“运行中”，说明进程在启动后卡住或被强制结束，
此时运行第 16 个入口查看本地诊断。

`最近一次调度结果` 的典型内容如下：

- `2026-09-07 10:00｜调度正常｜Data API 本轮无需采集｜飞书业务数据无变化`
- `2026-09-07 11:00｜调度正常｜Data API 已采集 1 个视频｜飞书已更新 5 条`
- `2026-09-07 12:00｜执行失败｜ExternalServiceError: ...`

该字段只判断最新视频 Data API 的实际采集情况，不用 Analytics 或 Reporting 的数据截止时间
反推调度是否运行；后两种 API 的官方数据本来就可能延迟生成。

## 四、换电脑

计划任务属于 Windows 本机，复制项目不会把任务本身复制过去。新电脑上应：

1. 安全迁移项目配置和凭据，或重新完成 YouTube 授权；
2. 运行 `1.首次配置.bat`，为新电脑建立运行环境；
3. 运行 `10.自动定时任务管理.bat` 并选择“安装或更新”；
4. 查看状态确认成功；
5. 暂停或卸载旧电脑的任务。

同一套飞书表格只允许一台电脑启用自动任务，避免重复写入和同时请求 API。

“账号非敏感配置”中原有的 `tracking_video_ids` 可以保留为兼容和应急补充。自动任务不会再依赖人工逐期添加新视频 ID，但当前版本的只读预览仍会使用该补充列表，因此暂时不要删除这条配置。

## 五、飞书“数据项目配置”应使用的值

- `latest_interval_minutes` = `60`
- `latest_hourly_tracking_hours` = `72`
- `latest_daily_collection_hour` = `8`
- `latest_analytics_interval_hours` = `24`
- `latest_reporting_interval_hours` = `6`
- `latest_tracking_days` = `28`

旧表中没有的配置键需要补充；已有的 7 天、24 小时等旧值需要改成上面这些值。远端飞书配置启用后优先于本地默认值。
