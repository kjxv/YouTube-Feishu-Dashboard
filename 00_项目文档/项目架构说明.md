# 项目架构说明

## 1. 目标

系统定位是可持续扩展的 YouTube 数据中心，不是若干相互独立的同步脚本。V1 交付“最新发布视频实时追踪”的完整纵向切片，并为后续频道历史、全部视频当前数据、每日历史、流量来源、收益与 Shorts 分析保留稳定接口。

## 2. 数据流

```text
飞书配置中心 + 本地敏感配置
           ↓
  配置校验 / 有效配置缓存
           ↓
数据需求规划器 → API 请求规划器
           ↓
Data API / Analytics API / Reporting API
           ↓
      标准化数据模型
           ↓
 公共 Repository / 主数据库
           ↓
       独立业务模块
           ↓
 字段映射 → 飞书业务表 → 仪表盘

统一调度器贯穿：到期判断、锁、重试、任务运行记录、恢复、心跳
公共 ArchiveService 贯穿：行数阈值检查、归档批次、可追踪记录
```

## 3. 组件边界

在磁盘上也按职责物理分区：

```text
03_公共核心框架/    OAuth、API、数据库、调度、日志、健康、归档
04_功能模块/        最新视频、频道历史、全部视频等独立业务板块
05_部署与运维/      Docker、systemd 等运行环境适配
90_开发与测试/      测试代码和开发辅助材料
```

中文目录用于人在资源管理器中识别职责；Python 包继续使用稳定英文名。公共框架包为 `youtube_feishu_dashboard`，业务模块包使用 `yfd_...` 前缀。

### 公共核心框架

负责配置加载与校验、OAuth/Token、YouTube 三类 API、飞书 HTTP、数据库会话、Repository、字段目录、字段映射、日志、调度、锁、重试、心跳、配置缓存与归档。

### 功能模块

模块通过依赖注入获得公共接口，只能声明任务、字段需求和业务转换。模块禁止直接读取 `.env`、创建 HTTP 会话、刷新 Token、打开数据库连接、安装系统计划任务或自行归档飞书表。

### 飞书配置中心

公共表至少包括：

| 表 | 作用 |
|---|---|
| API 字段字典 | 展示/校验系统支持的数据能力，不代表当前一定抓取 |
| 模块字段需求与映射 | 决定模块启用字段、标准字段到业务表列名的映射 |
| 数据项目配置 | 启停、间隔、追踪窗口、归档阈值等 |
| 账号非敏感配置 | 频道 ID、目标表 ID、时区等可运营配置 |

敏感 App Secret、OAuth 客户端和 Token 永不写入上述表或 Git。飞书配置读取失败时，系统仅在缓存未过期且通过校验的情况下使用“最近一次有效配置”，同时记录降级状态。

## 4. 数据库

所有模块共享一个数据库和统一模型。核心表覆盖频道、视频、真实抓取快照、字段能力、配置缓存、任务定义状态、任务运行记录、分布式/进程锁、系统心跳和归档批次。

数据库 URL 决定适配器：

- 本地默认：`sqlite:///data/yfd.db`
- VPS 推荐：`postgresql+psycopg://...`

业务层不判断数据库类型，不使用 SQLite 专有 SQL。Schema 只通过 Alembic 迁移演进。

## 5. 调度和断档

- `run-once`：明确运行一个任务，适合手工排错。
- `tick`：扫描已注册任务，只运行真实到期的任务，适合 Windows 计划任务、cron/systemd timer。
- `daemon`：后续扩展，仍调用相同任务注册表和锁。
- 每次任务先竞争带过期时间的数据库锁，避免重复运行。
- 失败按任务重试策略记录下一次时间；成功时间与下一次到期时间均持久化。
- 电脑关机期间没有抓取，就没有快照；重新开机后运行一次当前真实快照，不生成假的半小时历史点。
- Analytics/Reporting 的按日历史数据若 API 本身支持真实补抓，可由对应模块按日期游标补抓，这与伪造实时快照不同。

## 6. VPS 和容器预留

程序不依赖 GUI、盘符或固定目录。所有路径来自项目根目录或环境变量，时区显式配置，命令返回标准退出码。`05_部署与运维/docker` 只提供可选构建入口；第一阶段仍以本地虚拟环境运行和验证为准。

## 7. 扩展点

- `YouTubeDataGateway`、`YouTubeAnalyticsGateway`、`YouTubeReportingGateway`
- `FeishuGateway`、`ConfigCenter`
- `Storage` / 专用 Repository Protocol
- `ScheduledTask` 与任务注册表
- `ArchiveService`
- 模块 `manifest`：模块 ID、版本、任务、字段需求

这些接口优先保持稳定；更换 SDK、数据库或部署方式不应迫使业务模块重写。
