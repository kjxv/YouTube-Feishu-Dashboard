# AI 项目导航

这份文档面向接手项目的 AI。目标是先建立正确心智模型，再按最短路径定位代码。

## 先读什么

1. 根目录 `AGENTS.md`：不可破坏的业务与工程约束。
2. 根目录 `ai_project_manifest.json`：机器可读的入口、模块、数据策略和验证命令。
3. 当前业务模块的 `README.md` 与 `manifest.py`。
4. 若修改飞书字段，再读公共字段目录、运行时映射与迁移代码。

不要从 `project_state.json` 倒推当前实现；它主要保存历史进度。当前事实以代码、版本化
字段目录、测试和本导航为准。

## 架构与数据流

```text
系统计划任务 / 人工命令
        ↓
统一 CLI 与 scheduler
        ↓
远程配置中心 + 本地 Settings
        ↓
业务模块 service（只处理业务语义）
        ↓
共享 YouTube 客户端 + Repository/Storage
        ↓
标准字段 ID
        ↓
运行时映射校验（标准 ID → 飞书真实列）
        ↓
幂等同步到飞书
```

`03_公共核心框架` 是可复用能力层；`04_功能模块` 是业务层。任何跨模块能力先放公共层，
但不要为了“统一”而把单一模块的业务判断搬进去。

## 字段事实来源

字段不是由飞书列名直接驱动。正确链路是：

```text
公共字段目录 JSON → 模块 manifest 默认映射 → 飞书共享映射表
→ runtime 校验后的映射 → service 输出的标准字段值
```

排查“字段有值但写错列”时，按这条链逐层检查。不要只看飞书截图，也不要把唯一键中的日期
直接当作展示日期。

## 频道历史日期口径

两张历史表只保留一个正在使用的业务日期列：`数据日期（太平洋时间）`。

| 记录类型 | `数据日期（太平洋时间）`含义 | 来源 |
|---|---|---|
| 每日采样快照 / 频道采样快照 | Data API 实际采集时刻对应的太平洋自然日 | `DATA_API_FETCHED_AT_PACIFIC` |
| Analytics日统计 | Analytics API 返回的官方太平洋 `day`，即截止日 | API `day` 维度 |

精确时间列只保存真实 API 获取时间及采样时间，使用太平洋时间并带真实 DST 偏移。
日期精度的 API `day` 不扩写成虚假的截止时刻。旧版北京时间、截止时间、`统计日期`
和 `记录日期` 字段在校验回填并备份后物理删除。看板应按
`记录类型 + 数据日期（太平洋时间）` 解释记录，不能把两类记录混为同一种数据。

## 常见改动路线

### 改字段

依次检查：公共 catalog → 模块 manifest → runtime 允许列表 → service 写值 → Feishu setup
迁移 → 历史 backfill → tests → 模块 README。

### 改调度

依次检查：模块 task → 公共 scheduler 注册 → 配置开关 → Windows/Linux 启动脚本 → 运维文档。

### 排查少数视频或日期缺失

先确认 Analytics API 是否真的返回该“视频 + day”组合，再检查长视频筛选、唯一键、运行时映射
和飞书写入计数。API 未返回不能补零，也不能提前创建占位行。
最新日只返回少量非零行时，必须比较同一视频过滤范围的控制总数与逐视频明细合计；两者不等
说明仍在部分结算，整日暂缓写入，不能仅凭“日期已经出现”认定该日完整。

## 迁移安全

本项目的一次性历史修复必须：先只读预览、核对三张表数量、确认时传入精确预期数量、写前
落地完整备份、数量变化即停止。字段迁移使用幂等命令，可以重复执行；不要在飞书手工删旧列。
