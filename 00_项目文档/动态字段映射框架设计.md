# 动态字段映射框架设计

## 1. 目标

本轮改造的目标不是单独支持“视频缩略图网址”，而是建立一条可复用的数据通道：

`API字段字典 → 启用的字段映射 → YouTube请求与提取 → 飞书字段类型适配 → 三表写入`

完成后，在支持范围内新增普通字段时，只需要维护飞书业务表和公共映射配置，不再为每个字段修改主程序。

## 2. 第一版支持范围

第一版优先支持 YouTube Data API 返回资源中的普通单值字段，包括：

- 字符串、整数、浮点数、布尔值；
- 日期时间和时长；
- 普通网址和飞书超链接；
- 可以通过明确官方字段路径读取、并写入同一业务记录的字段。

“视频缩略图网址”只是验收样例之一，不在程序里写专用分支。

## 3. 暂不自动化的边界

以下变化通常不仅是“增加一列”，仍需要专门配置、模板或代码：

- YouTube Analytics API 的指标、维度、日期范围和筛选条件组合；
- YouTube Reporting API 报表任务、下载和明细展开；
- 一个 API 数组需要拆成多行记录；
- 跨视频、跨时间档或跨表聚合计算；
- 没有明确公式的业务自定义计算；
- 飞书附件、人员、关联记录、查找引用等复杂字段。

检查程序必须明确报告这些字段“不属于普通自动映射范围”，不能静默跳过。

## 4. 配置职责

### 4.1 API字段字典

每个可自动提取字段至少需要提供：

- 标准字段 ID：程序和配置之间的稳定主键；
- API 来源：Data、Analytics 或 Reporting；
- 官方字段路径：例如 `snippet.thumbnails.high.url`；
- API 数据类型：例如 `string`、`integer`、`datetime`；
- Data API 的 `part`；
- 数据层级：频道、视频、播放列表等；
- 查询组或请求模板；
- 所需 OAuth 权限；
- 是否启用，以及是否属于普通自动映射范围。

中文名称和说明用于识别，不参与程序匹配。

### 4.2 模块字段需求与映射

每条启用映射至少需要提供：

- 模块 ID；
- 目标表 ID；
- 飞书列名；
- 标准字段 ID；
- 启用状态。

标准字段 ID 关联 API 字段字典，飞书列名关联目标业务表。程序不依赖中文显示名称做推断。

### 4.3 飞书字段类型

不建议在映射表中再手工维护一列“目标字段类型”。程序应通过飞书 API 读取目标表的实时字段结构，并取得：

- 字段名；
- 字段 ID；
- 字段类型；
- 字段属性。

飞书实时结构是唯一权威来源。这样把“单行文本”改成“超链接”后，不需要同时修改映射表中的类型备注，也避免两处配置不一致。

## 5. 编译后的运行计划

第 9 个只读检查应把远端配置编译成一份可执行计划：

1. 读取模块的所有启用映射；
2. 用标准字段 ID 关联 API 字段字典；
3. 按 API 来源、资源层级、查询组和 `part` 合并请求；
4. 读取每个目标表的实时字段结构；
5. 为每条映射确定官方提取路径和飞书目标类型；
6. 检查重复映射、缺失列、未知标准字段、不支持的数据形态和类型冲突；
7. 输出“可执行”或“禁止执行”以及逐字段原因。

只要存在会造成结果错误的配置问题，就必须在写入前失败；不允许把缺失字段悄悄当作空值写入。

## 6. 通用提取器

YouTube Data API 普通字段由统一的路径提取器读取：

- 输入：原始 API 资源和字段字典中的官方路径；
- 输出：标准字段 ID 到原始值的映射；
- 路径不存在：区分“合法空值”和“配置/实现不支持”；
- 同一请求所需的 `part` 由启用映射自动合并；
- 业务模块只声明记录粒度和业务计算，不再逐个罗列普通 API 字段。

## 7. 通用类型适配器

写入前根据飞书实时字段类型选择适配器。第一版至少覆盖：

- 文本：转为字符串；
- 数字：校验并转为整数或浮点数；
- 复选框：转为布尔值；
- 日期：转为飞书要求的时间值；
- 单选/多选：转为合法选项值；
- URL/超链接：转为飞书要求的链接结构；
- 空值：按字段类型和更新策略处理。

适配器按“飞书字段类型”注册，不能为“缩略图”“标题”等业务名称写专用逻辑。

## 8. 三个日常入口的职责

- 第 9 个“只读检查三表配置”：编译动态计划并验证所有映射、API提取能力、目标列和字段类型；不获取 YouTube 业务数据，不写业务表。
- 第 8 个“只读预览最新视频”：按动态计划读取 YouTube，显示标准字段值及转换预览；不写飞书业务表。
- 第 6 个“运行一次最新视频”：强制先执行与第 9 个相同的预检查；全部通过后再获取、转换并写入三张业务表。

第 6 个入口必须自带预检查，不能要求用户记住先手工运行第 9 个和第 8 个。第 9、8 是配置调整后的诊断和确认工具。

## 9. 新增普通字段后的目标操作流程

1. 在目标飞书业务表新增字段并选择字段类型；
2. 确认 API 字段字典中已有对应标准字段 ID 和完整提取元数据；
3. 在模块字段映射表新增或启用映射；
4. 运行第 9 个检查，修正所有错误；
5. 可选运行第 8 个预览，确认真实值和转换结果；
6. 运行第 6 个正式同步。

如果字典中没有该字段，先补充字典元数据；如果属于第 3 节的复杂边界，则进入模块开发流程。

## 10. 分步实施与验收

1. 收敛中断状态，固定本设计契约；
2. 建立 YouTube Data API 普通单值字段通用提取器；
3. 建立飞书实时字段类型识别和通用适配器；
4. 升级第 9、第 8、第 6 的动态计划和强制预检查；
5. 用多种字段、空值、错误路径和类型冲突完成自动化测试；
6. 更新正式运行环境并完成小规模真实验收。

最终验收不能只测试缩略图网址：还需再选择至少一个此前主程序没有硬编码的普通字段，仅修改字典/映射配置便成功预览并同步，以证明框架确实通用。
