# 日常使用与扩展指南

## 一、以后最常用的操作

在 Windows 上，平时只需要双击：

`01_启动脚本/Windows/6.运行一次_最新视频.bat`

运行前，先在飞书“账号非敏感配置”的 `tracking_video_ids` 填写 1～10 个视频 ID。第 6 个入口会完成一轮真实闭环：读取飞书配置中心 → 解析手动视频列表 → 确定所需字段和三张目标表 → 批量读取这些 YouTube 视频 → 写入本地数据库 → 逐视频幂等更新主表、真实快照和同期对比记录。

“幂等”表示同一个业务键重复运行时更新已有记录，不会无条件制造重复行。电脑关机期间也不会补造并不存在的历史快照。

频道每日统计使用 `11.只读检查_频道数据.bat` 做只读检查，使用 `12.运行一次_频道数据.bat` 做一次人工同步。它只处理长视频，并与最新视频模块共用第 10 个入口安装的同一个 Windows 计划任务。

## 二、十六个 Windows 入口分别做什么

| 入口 | 什么时候使用 | 是否写业务数据 |
|---|---|---|
| `1.首次配置.bat` | 第一次安装、重建运行环境 | 会初始化本地环境和数据库 |
| `2.YouTube授权.bat` | 第一次授权或 Token 失效 | 只更新本地 OAuth Token |
| `3.初始化飞书配置中心.bat` | 第一次创建或补齐四张公共配置表 | 会幂等补齐公共配置 |
| `4.中文化升级飞书配置表.bat` | 旧版配置表需要中文说明时 | 会幂等升级公共配置 |
| `5.系统检查.bat` | 授权、密钥、网络或连接异常时 | 只检查，不写三张业务表 |
| `6.运行一次_最新视频.bat` | 日常手动执行一轮完整同步 | 会写本地数据库和三张业务表 |
| `7.调度滴答.bat` | 只供 Windows 计划任务调用 | 仅运行真正到期的任务 |
| `8.只读预览_最新视频.bat` | 在线核对指定视频是否存在、属于当前频道及预计写入 | 不写三张业务表 |
| `9.只读检查_三表配置.bat` | 改过视频列表、字段、映射或 Table ID 后 | 不请求 YouTube，不写三张业务表 |
| `10.自动定时任务管理.bat` | 安装、查看、暂停、恢复统一 Windows 任务 | 管理系统任务，本身不直接采集 |
| `11.只读检查_频道数据.bat` | 检查频道模块三张表、字段和映射 | 不写业务数据 |
| `12.运行一次_频道数据.bat` | 人工执行一次频道每日统计 | 会更新频道模块三张业务表 |
| `13.补建频道48小时字段.bat` | 单独补建48小时字段和共享映射 | 只改字段与映射，不采集 YouTube |
| `14.运行电脑升级并验收.bat` | Git 更新后安装新版、补齐状态表和字段并做只读验收 | 不写视频或频道业务数据 |
| `15.启用并首次同步频道数据.bat` | 验收通过后启用频道模块并做首次同步 | 会写频道模块三张业务表 |
| `16.诊断定时任务.bat` | 自动任务未更新、卡住或疑似没启动时 | 只读检查本机任务、进程、锁、心跳和日志 |

日常不要反复运行 1～4，也不要把 7 当成普通手动入口。最新视频手动同步用 6，频道数据手动同步用 12；排查问题先用相应只读入口。

## 三、一轮任务的执行逻辑

```text
飞书公共配置表
  ├─ 数据项目配置：多久采集、追踪多少天
  ├─ 账号非敏感配置：追踪哪些视频、哪个频道、三张业务表写到哪里
  ├─ 模块字段需求与映射：标准字段写入哪张表的哪一列
  └─ API字段字典：标准字段来自哪个 YouTube API
          ↓
程序生成请求计划并读取 YouTube
          ↓
本地数据库保存真实状态、任务锁和历史快照
          ↓
视频追踪主表 + 视频实时快照表 + 视频同期对比表
```

公共配置表决定“采什么、写到哪、字段怎样对应”；模块代码决定“如何调用 API、如何计算增量和对比、如何幂等写入”。只在飞书增加一条映射，不会凭空产生代码尚未实现的数据。

## 四、调整现有设置

### 修改采集间隔或追踪天数

进入飞书的“数据项目配置”，只修改 `配置值`：

- `latest_interval_minutes`：系统整点检查间隔，当前为 60 分钟。
- `latest_hourly_tracking_hours`：发布后小时级追踪时长，当前为 72 小时。
- `latest_daily_collection_hour`：之后每日采集整点，当前为北京时间 8 点。
- `latest_reporting_interval_hours`：Reporting API 检查间隔，当前为 6 小时。
- `latest_tracking_days`：最长追踪天数，当前为 28 天。

自动运行请使用 `10.自动定时任务管理.bat`；详细规则见
`00_项目文档/自动定时采集说明.md`。

不要修改 `配置键`，也不要删除带 `【关键字段｜请勿删除或改名】` 说明的字段。当前版本尚未实现分阶段周期；当前60分钟间隔会统一应用于整个追踪窗口。

### 修改频道或业务表

进入“账号非敏感配置”，只修改对应记录的 `配置值`：

- `youtube_channel_id`：目标频道 ID；留空时尝试识别 OAuth 授权账号。
- `latest_video_main_table_id`：视频追踪主表 ID。
- `latest_video_snapshot_table_id`：视频实时快照表 ID。
- `latest_video_comparison_table_id`：视频同期对比表 ID。
- `channel_history_video_main_table_id`：频道模块的视频主表 ID。
- `channel_history_video_history_table_id`：频道模块的视频历史数据表 ID。
- `channel_history_channel_history_table_id`：频道历史数据表 ID。

改完以后先运行 9，再运行 8，两个只读检查通过后才运行 6。

频道模块的运行开关和时间在“数据项目配置”中：

- `channel_history_enabled`：是否启用频道每日统计。
- `channel_history_daily_collection_hour`：北京时间每日采集小时，默认 8。
- `channel_history_timezone`：频道快照和任务日期使用的时区，默认 `Asia/Shanghai`。

频道字段或 Table ID 修改后先运行 11，通过后才运行 12。

开发电脑把新版本同步到 Git 后，真正运行定时任务的电脑可双击 `14.运行电脑升级并验收.bat`。该入口会安装当前项目、检查在线连接、幂等创建“系统运行状态”表、确认48小时字段与映射，再执行两个模块的只读检查；它不会采集 YouTube 数据、不会写视频或频道业务表，也不会自动开启频道模块。第14个入口通过后，再双击 `15.启用并首次同步频道数据.bat`；首次同步失败时会自动把频道开关恢复为关闭。

## 五、增加或调整一个字段

按以下顺序操作：

1. 在“API字段字典”中找到需要的 `标准字段ID`、API 来源、官方字段和数据类型。找不到时，先确认它是官方 API 字段还是程序计算字段。
2. 在目标业务表中新建一列；列名和字段类型要符合实际数据。
3. 在“模块字段需求与映射”增加或修改记录，填写模块 ID、目标表 ID、飞书列名、标准字段 ID，并启用。
4. 确认最新视频模块已经请求或计算这个标准字段。若模块清单和代码尚未实现，就需要先修改模块代码；仅增加飞书记录不会自动生成该值。
5. 运行 9 检查目标列与映射，再运行 8 查看 API 返回，最后运行 6 做一次真实验证。

可以自由修改中文名称、用途说明和备注等阅读辅助列。不要随意修改模块 ID、标准字段 ID、配置键、目标表 ID、飞书列名等程序关键内容。

## 六、开发一个新功能模块

1. 在 `04_功能模块` 新建独立目录和稳定英文包名。
2. 声明模块 ID、中文名、所需标准字段和输出字段。
3. 在模块内部实现业务计算与任务流程；OAuth、飞书客户端、数据库、锁和调度继续复用 `03_公共核心框架`。
4. 在公共配置表增加目标表、字段映射和项目配置。
5. 为模块增加只读预览、结构检查、自动化测试和 dry-run。
6. 所有只读检查通过后，只运行一次真实小测试并回读验证，再考虑加入统一调度。

频道历史模块已经实现；全部视频当前数据目录仍是模板，不能仅靠启用配置开始采集。

## 七、自动运行与 VPS

本步骤没有替你安装系统定时任务。

Windows 自动运行请使用 `10.自动定时任务管理.bat` 安装。系统任务每小时触发一次 `7.调度滴答.bat`；最新视频与频道每日统计都由同一调度入口判断是否真正到期。不要为两个模块建立两个系统任务。

测试阶段可查看独立的“系统运行状态”表。它每次调度唤醒都会更新同一行，因此业务数据没有
变化时也能判断任务是否启动、是否完成、有没有到期任务。若 Windows 显示 `0x41301`，表示
任务仍在运行；直接双击 `16.诊断定时任务.bat` 获取完整诊断。更新版本后还应在第 10 个入口
选择一次“安装或更新”，才能把 45 分钟超时等新版系统任务设置应用到 Windows。

状态表中的 `最近一次调度结果` 是日常查看入口：它把北京时间整点、调度状态、最新视频
Data API 是否真实采集、飞书业务表实际更新条数合并为一句话。`本轮飞书写入记录数=0`
不等于调度失败；要结合该摘要区分“无需采集”“采集后数据未变化”和“执行失败”。

换电脑或重建本地数据库后，频道模块会按三张表的业务唯一键安全认领已有飞书记录。同键存在多行时会停止。迁移时不要用一台电脑的 SQLite 数据库覆盖另一台电脑原有数据库；应先暂停自动任务、备份本地配置和数据库、升级程序、运行第 11 个只读检查，再人工运行第 12 个入口验收。

迁移 VPS 前先暂停 Windows 触发器，并安全迁移 `.env`、OAuth 文件和当前 SQLite 数据库，
不能只拉 Git 后创建空数据库。VPS 先运行 `Linux_VPS/升级并验收.sh`，再分别人工运行一次
最新视频和频道任务，最后使用 `Linux_VPS/自动任务管理.sh install` 安装统一 systemd timer。
当前已验收路线是单机 SQLite；PostgreSQL/Docker 留待后续专项迁移测试。不要让 Windows 和
VPS 同时采集同一账号。完整步骤见 `00_项目文档/VPS部署说明.md`。

## 八、调试结束后的安全收尾

当前第一闭环已经跑通。因为旧飞书 App Secret 曾出现在截图中，调试结束后必须：

1. 在飞书开放平台重置该应用的 App Secret。
2. 把本机 `.env` 中的 `YFD_FEISHU_APP_SECRET` 替换为新值。
3. 运行 `5.系统检查.bat`，确认飞书在线连接通过。

不要把新 Secret 发到聊天、截图、GitHub 或飞书非敏感配置表。项目也不会自动提交或推送 GitHub。
