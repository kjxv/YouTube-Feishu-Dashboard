# 手动多视频追踪设计

## 1. 目标

把“自动选择频道最新一个视频”改造成一个统一的手动追踪入口：

- 配置 1 个 YouTube 视频 ID 时，只追踪该视频。
- 配置多个视频 ID 时，同时追踪这些视频。
- 所有视频共用现有的 API 字段字典、字段映射和三表写入规则，不为每一期复制配置。
- 删除某个 ID 后停止它的后续采集，但保留已经写入的历史记录。
- 手动模式下配置错误时必须停止并说明原因，禁止悄悄退回“最新视频”。

## 2. 当前代码审计结论

当前的单视频限制集中在两个入口：

1. 正式同步服务先读取频道上传列表，再只取 `latest_ids[:1]` 和第一条视频资源。
2. 第 8 个只读预览采用同样的“只取最新一条”逻辑。

以下底层能力已经可以复用：

- YouTube Data API 客户端已经支持批量传入视频 ID，并按官方单次最多 50 个 ID 自动分批。
- 主表使用视频 ID 作为唯一键；快照编号和同期对比编号也都包含视频 ID，多视频之间不会天然撞号。
- 字段字典、动态请求计划、字段提取、飞书类型转换和三表映射都按“表 + 标准字段”工作，与视频数量无关。
- 每个视频的增量值会读取该视频自己的上一条快照，不会混用其他视频的数据。

因此，本次改造不需要推翻现有框架，主要改造“追踪对象配置、批量校验、逐视频执行和汇总结果”。

## 3. 统一配置约定

在飞书“账号非敏感配置”中增加一个非敏感配置键：

- 配置键：`tracking_video_ids`
- 中文配置名：`当前追踪视频ID列表`
- 配置值：一个或多个 YouTube 视频 ID
- 支持分隔符：换行、英文逗号、中文逗号、英文分号、中文分号

解析规则：

1. 去掉首尾空格和空项。
2. 保留用户填写的先后顺序。
3. 重复 ID 自动合并，并在检查结果中提示。
4. 每个 ID 必须满足 YouTube 视频 ID 的基本格式：11 位，仅允许英文字母、数字、下划线和连字符。
5. 第一版最多同时启用 10 个视频；超出时停止并提示，不自动截断。
6. 配置为空、全部无效或缺少配置时，正式同步必须停止，不自动选择最新视频。

一个配置键同时兼容单视频和多视频，后续不需要再维护两套开关。

## 4. 正式写入前的安全检查

每次正式同步必须先完成整批预检查，再产生任何本地业务记录或飞书业务写入：

1. 读取并解析全部手动视频 ID。
2. 一次批量调用 YouTube `videos.list` 获取全部视频资源。
3. 核对每个配置 ID 都有返回结果；不存在、已删除、私密或当前账号不可访问的 ID 列为错误。
4. 核对每个视频都属于当前配置的 YouTube 频道，防止误追踪其他频道的视频。
5. 汇总整批错误。只要存在格式错误、缺失视频或频道不匹配，正式同步整批停止，保证不会写入一半后才失败。
6. 第 8 个只读预览则逐条报告成功、失败、过期和预计写入内容，不写本地业务数据和飞书业务表。

## 5. 追踪期限和增删规则

- `latest_tracking_days`（当前默认 7 天）继续作为每个视频的追踪期限。
- 超过期限的视频标记为“已过期并跳过”，不再生成新快照；它不会阻止同一列表中其他有效视频继续同步。
- 从配置列表中删除视频 ID：从下一次运行开始停止采集，既有主表、快照和同期对比记录不删除。
- 重新加入曾删除的视频 ID：从重新加入后的真实运行时间继续采集，不补造中断期间的快照。
- 修改追踪天数只影响下一次运行后的资格判断，不回写或删除历史数据。

## 6. 多视频写入规则

对每个仍在追踪期内的视频，继续执行同一套通用流程：

1. 获取 API 基础字段并执行动态字段映射。
2. 更新视频追踪主表的一行。
3. 写入当前真实时间桶的一条快照。
4. 写入同期对比的“当前视频、最近 10 条平均、最近 10 条中位数”三类记录。

因此，通常每个有效视频最多产生 5 次业务写入；实际次数会受幂等更新和相同时间桶影响。容量检查应在每次任务中按业务表统一执行，避免随视频数量重复请求相同的表记录数。

任务结果需要从原来的单个视频结果升级为：

- 请求 ID 数量、有效数量、过期数量、失败数量。
- 每个视频的状态、跳过原因和写入统计。
- 全部视频合计的主表、快照、同期对比和飞书写入次数。

## 7. 兼容与边界

- 不修改现有标准字段 ID，不要求重做三张表映射。
- 第 9 个脚本仍负责检查三表结构、字段映射和飞书实时类型；另外增加手动视频配置的离线格式检查。
- 第 8 个脚本负责在线只读验证每个指定视频及展示预计写入。
- 第 6 个脚本负责在所有预检查通过后正式批量同步。
- “自动追踪最新视频”如果以后仍需要，只能作为一个明确、独立的可选模式实现；手动模式永远不隐式回退。
- 第一版仅支持同一个已授权频道内的多个视频。跨频道追踪需要独立账号/授权和额外的数据归属规则，不在本轮范围内。

## 8. 分步实施计划

1. 审计单视频假设并确定配置、安全和期限规则（本文，已完成）。
2. 增加 `tracking_video_ids` 公共配置、解析、去重、格式校验和最多 10 个限制（已完成）。
3. 把正式服务改为批量获取、整批预检查和逐视频处理，并补齐本地自动化测试（已完成）。
4. 升级第 8 个只读预览，逐个展示指定视频、期限状态和三表预计写入（已完成）。
5. 升级第 6 个正式同步及第 9 个配置检查，汇总多视频结果并保证先检查后写入（已完成）。
6. 安装到正式运行环境，先只读验收，再用少量指定视频完成一次在线三表同步验收（已完成）。

每一步完成后单独验证并暂停，未经用户确认不进入下一步。

## 9. 第 2 步实现结果

- “账号非敏感配置”模板已增加 `tracking_video_ids`，以后执行配置中心升级时会幂等补建该记录，不覆盖用户已经填写的值。
- 新增独立配置解析器，支持单个或多个 ID、换行及中英文逗号/分号。
- 解析器按填写顺序去重，并单独报告重复 ID；重复项不占用最多 10 个有效视频的额度。
- 空配置、非法 11 位格式和超过 10 个不同 ID 都会抛出明确配置错误；空配置不会回退到最新视频。
- 解析器尚未接入正式同步、只读预览或第 9 个检查入口，留待后续步骤逐层接入。
- 本地全套 69 项测试、Ruff 和严格 Mypy 均通过；没有发生外部请求或业务写入。

## 10. 第 3 步实现结果

- 正式追踪服务已停止读取“频道最新上传列表”，改为一次批量请求配置中的全部视频 ID。
- 批量响应会恢复成用户配置顺序，并统一检查缺失视频、重复返回、未请求视频、授权频道不一致和视频频道归属不一致。
- 任一配置或资源检查失败时，整批在容量检查、本地频道/视频/快照保存和飞书写入之前停止。
- 所有有效视频的时长和动态 API 字段也会先解析；后一个视频解析失败不会造成前一个视频提前写入。
- 通过预检查后，所有有效视频在同一数据库事务中保存；随后逐视频共用同一映射写入主表、快照表和同期对比表。
- 快照表和同期对比表的容量只在每次任务中各检查一次，不随视频数量重复检查。
- 过期视频只报告并跳过自身，同一列表中的有效视频继续同步；结果保持用户配置顺序并提供逐视频状态与合计写入数。
- 服务已实现但尚未连接第 6/8/9 个用户入口；本地全套 74 项测试、Ruff 和严格 Mypy 均通过，没有外部请求或业务写入。

## 11. 第 4 步实现结果

- 第 8 个只读预览已从“自动读取最新一条”改成读取账号配置中的 `tracking_video_ids`，不再调用频道上传列表。
- 多视频预览始终按用户填写顺序输出，并逐条区分：可同步、已过期、无法访问、频道不匹配和资源解析失败。
- 单条失败不会遮住其他视频的预览结果；重复或意外 API 返回会作为阻止正式运行的响应警告展示。
- 每条可同步视频显示 API 标准值、动态字段缺失/空值、按飞书实时类型转换后的字段预览，以及主表1、快照1、同期对比3的最多5次预计写入。
- 已过期或错误视频预计写入为0；汇总会给出可同步、过期、失败数量和最多总写入数。
- 为兼容原有单视频查看习惯，只有一个有效视频时仍保留顶层 `video`、`tracking` 和字段预览。
- 源码中的第 8 个入口已经连接手动配置，但线上配置记录和正式运行环境尚未更新；本地全套75项测试、Ruff和严格Mypy通过。

## 12. 第 5 步实现结果

- 第 6 个正式同步入口会在创建 YouTube 客户端和进入业务写入前读取并严格校验 `tracking_video_ids`，再把同一份保序去重后的视频列表交给批量追踪服务。
- 第 6 个入口的安全演练结果会显示视频 ID 列表和数量；正式结果继续输出逐视频状态以及主表、快照表、同期对比表和飞书写入合计。
- 第 9 个只读检查新增 `tracking_video_config` 报告，显示视频 ID、有效数量、提交数量和被移除的重复项；空值、格式错误或超限会把完整三表同步安全状态改为不可运行。
- 第 9 个入口只检查配置格式、数量和重复项，不请求 YouTube；视频是否存在、是否可访问和是否属于当前频道仍由第 8 个只读预览或第 6 个正式同步确认。
- Windows 使用说明和日常指南已改为同一套手动列表流程；本地专项25项、全套78项测试、Ruff和严格Mypy均通过。
- 本步骤没有访问真实 YouTube 或飞书、没有写业务表、没有安装正式环境、没有提交或推送 GitHub。
