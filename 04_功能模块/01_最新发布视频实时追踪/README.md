# 最新发布视频实时追踪

- Python 包：`yfd_latest_video_tracker`
- 调度任务 ID：`latest-video-tracker`
- 状态：第一阶段 V1 已实现

该模块每次运行都会读取授权频道的上传列表，自动发现最近 28 天内已经公开的长视频。发布时间最新的一期会被标记为“当前追踪视频=是”，窗口内其他视频继续保留“追踪中”，但标记为“否”；超过 28 天后才改为“追踪结束”。“账号非敏感配置”中的 `tracking_video_ids` 只作为兼容和应急补充，保留现有值即可，今后发布新视频不需要再手动添加 ID。

主表按视频 ID 保证一视频一行；快照表按视频 ID 和真实采集时间保存历史。若 Windows、VPS 或重建后的本地数据库曾把同一视频写成多行，下一轮任务会保留一条主记录、重新绑定并删除多余主记录。快照表的“当前追踪视频”是查找引用字段，会随主表状态一起显示，不会逐条改写历史快照。

## 第一次运行前的安全检查

先运行只读预览：

```powershell
.\.venv\Scripts\yfd.exe modules preview latest_video_tracker
```

该命令仍用于核对配置中保留的手动补充视频，逐条显示可访问性、期限状态、标准字段和预计写入，但不会写入飞书或业务数据库。自动发现由正式同步和整点调度执行。OAuth
访问令牌过期时，公共授权组件可能在本地刷新 `secrets/youtube_token.json`。

再运行三表同步前检查：

```powershell
.\.venv\Scripts\yfd.exe modules validate-sync latest_video_tracker
```

它读取飞书配置中心和三张业务表的字段结构，同时检查作为兼容补充的 `tracking_video_ids` 格式、数量和重复项。报告会显示视频列表检查结果、Table ID、远端可访问性、启用映射数、缺失列以及三表写入实现状态。它不会请求 YouTube；自动发现结果由正式同步确认。

代码职责：

- `manifest.py`：模块身份、所需 API 字段和默认飞书字段映射。
- `service.py`：最新视频追踪业务流程和数据转换。
- `preview.py`：只访问 YouTube 的安全预览，不依赖数据库或飞书。
- `task.py`：接入公共调度器的薄适配层。

OAuth、YouTube/飞书客户端、数据库连接、归档、锁和重试均来自 `03_公共核心框架`。

## 每小时播放速度的口径

`每小时播放速度` 当前由主程序按真实采集间隔计算：

- 有上一条快照：`(当前累计播放量 - 上一条累计播放量) ÷ 两次真实采集间隔小时数`；
- 第一条快照：`当前累计播放量 ÷ 发布后实际小时数`；
- 播放量为空时留空，时间差不大于 0 时写 0，结果保留两位小数。

因此它表达的是“最近一个真实采集区间的速度”，并不等于“发布以来平均每小时播放量”。计划任务晚运行、电脑关机或网络中断时，分母仍使用真实间隔，不会默认按一小时计算。

飞书公式可以作为透明校验，但若要完全复现后续快照的主程序结果，还必须另外保存“距上次采集分钟数”。仅使用 `本周期新增播放量 ÷ 1`，只在两次采集恰好相隔一小时时成立。当前阶段保留主程序计算值作为同步和同期对比的数据源，不把它替换成依赖排序位置的飞书公式。
