# 频道历史数据

- Python 包：`yfd_channel_history`
- 模块 ID：`channel_history`
- 调度任务 ID：`channel-history-daily`
- 状态：V1 已实现，默认由飞书配置开关控制是否启用

## 采集范围

当前版本只统计公开视频中的长视频，Shorts、直播/即将直播和非公开视频不写入三张业务表。

- 视频主表：每个长视频一行，保存标题、发布时间、当前累计播放量等最新状态。
- 视频历史数据：保存北京时间每日 Data API 累计快照，以及 YouTube Analytics 已结算自然日播放量。
- 频道历史数据：保存频道公开累计快照，以及 Analytics 每日播放和订阅变化。

频道采样快照还会保存 `estimatedRevenue` 的过去 28 个太平洋自然日合计，货币固定为 USD。该值对应 YouTube Studio 概览中的“估算收入”，不是仅广告部分的 `estimatedAdRevenue`。YouTube 公共 API 的最近已结算日通常落后于 Studio（实际截止日更早），因此同一时刻可能暂时小于后台显示值；任务明细会同时记录请求窗口与 API 实际数据截止日。

仪表盘展示当前收入时，筛选 `记录类型 = 频道采样快照` 且 `是否最新频道快照 = 是`，再汇总 `近28日估算收入（USD）`。不要使用最大值，因为滚动 28 日收入可能上涨也可能下降。

Analytics 日统计使用三个明确分工的日期字段：

- `数据截止日期`：API `day` 维度原样返回的太平洋日期，用于查底稿和排查；
- `统计日期`：将该太平洋统计日的结束时刻换算到北京时间后取得的北京日期，供看板使用；
- `记录日期（北京时间）`：本次 Analytics API 数据获取时刻换算后的北京日期。

`Analytics API 数据获取时间（北京时间）` 继续保留精确到秒的真实请求时间。
日报不再映射 `Analytics API 数据截止时间（北京时间）`，旧列会保留但停止写入。
太平洋自然日横跨两个北京自然日，所以 `统计日期` 是方便查看和筛选的北京结束日标签，
不能把其播放量解释为该北京日期 00:00–23:59 的完整自然日播放量。

视频主表及其每日快照中的 Analytics 截止时间取该视频实际返回的最新逐视频日统计，
不再复用整个频道或整批视频的最晚日期。频道采样快照的近 28 日收入仍使用其
独立收入报表的截止日期。

部署本次改动后，每日任务只会修正查询回看窗口内的历史行；更早的已写入行不会
自动回填。可先在 VPS 项目环境执行
先执行 `python -m youtube_feishu_dashboard feishu enable-channel-analytics-date-fields`
新增 `数据截止日期` 列、调整共享映射并停用旧的日报截止时间映射。然后执行
`python -m youtube_feishu_dashboard feishu backfill-channel-analytics-daily-dates`
进行只读预检。核对返回的视频、频道待修正行数 `N` 和 `M` 后，再执行同一命令并添加
`--expected-video-count N --expected-channel-count M --confirm`；如实时数量不同，程序会拒绝写入。
确认后程序会先在
`runtime/backups/` 保存这些记录的完整原始内容，再分批仅更新北京截止时间和
三个日期字段。此回填不修改播放量、唯一键或最新标记。

频道级日报与按视频拆分的日报可能并非同时完成结算。程序只为 YouTube
Analytics API 实际返回的“视频 + 日期”组合写入视频日统计；缺少明细的日期
保持未结算，不再把“接口未返回”写成播放量 0。任务明细分别记录频道级和
视频级的数据截止日，便于发现两种报表之间的结算时间差。API 明确返回的
真实 0 值仍会正常保留。

若最新日期出现“长视频汇总大于 0、所有逐视频明细合计为 0”的占位结果，
程序会把该日视为未结算并停止写入，等待真实明细返回后再自动补齐。

已经被旧版本写入飞书的占位零可使用一次性清理命令处理。命令必须同时指定
统计日期和预期记录数；数量不完全一致时拒绝写入。清理前先把完整原始记录备份
到 VPS 本地，再删除匹配的飞书行及其本地绑定；真实明细到达后程序会重新创建。

## 发布后 48 小时播放量

频道视频主表预留三个稳定字段：

- `发布后48小时播放量`：用于 48 小时表现排行榜；
- `48小时样本发布后分钟数`：显示真实样本距离发布时间多少分钟，可用 `ABS(该值-2880)` 查看误差；
- `48小时样本采集时间（北京时间）`：保留实际取样时间，便于核查。

程序从本地保存的真实 Data API 快照中选择最接近发布后 2,880 分钟的一条，默认允许前后 90 分钟。等距时优先使用 48 小时之后的样本；超过容差或没有真实快照时保持为空，不用 Analytics 太平洋自然日或当前累计值补造。旧视频如果当时没有保存 48 小时附近快照，无法准确回填；新视频需在发布后 72 小时内保持最新视频追踪任务正常运行。

本地代码、公共字段字典和飞书视频主表已经支持这三个值；三条共享映射也已启用。升级命令 `feishu enable-channel-48h-fields` 可重复执行：已有正确字段会复用，缺失项才会创建，字段类型冲突或重复映射时会在业务写入前停止。

## 调度规则

系统计划任务每小时唤醒统一调度器。频道任务在北京时间每天 08:00 后首次到期时运行一次；当天成功后不会重复采集。电脑在 08:00 关机时，恢复后会补做当天的一次真实采集，但不会伪造关机期间数据。

项目配置中的 `channel_history_enabled` 决定是否注册任务。频道任务和最新视频任务共用同一个 Windows 计划任务，不要为它们分别创建系统任务。

## 换电脑安全

三张表都使用稳定业务唯一键。新电脑或新数据库缺少本地飞书绑定时，程序会先按唯一键认领飞书已有记录，再更新原行；只有远程不存在时才创建。若同一唯一键存在多行，任务会在业务写入前停止，避免猜测或继续制造重复数据。

任务日志中的关键计数：

- `feishu_bindings_adopted`：本轮从飞书认领的已有记录数；
- `feishu_records_changed`：本轮实际新增或更新的记录数；
- `feishu_batch_requests`：本轮实际飞书批量写请求数。
- `forty_eight_hour_samples_found`：本轮长视频中找到合格48小时真实快照的数量；
- `forty_eight_hour_samples_missing`：本轮仍缺少合格48小时真实快照的数量。旧记录认领不会改变这两个采样结果。

## Windows 操作入口

1. `11.只读检查_频道数据.bat`：只读检查配置、三张表、字段和映射。
2. `12.运行一次_频道数据.bat`：立即执行频道任务；要求远程模块开关已启用。
3. `10.自动定时任务管理.bat`：安装、查看、暂停或恢复统一 Windows 计划任务。
4. `13.补建频道48小时字段.bat`：换电脑或重建表结构后，幂等补建三个48小时字段和共享映射。
5. `14.运行电脑升级并验收.bat`：安装 Git 更新后的当前项目，依次完成在线健康检查、字段确认和频道三表只读验收；不运行正式采集。
6. `15.启用并首次同步频道数据.bat`：只读检查通过后开启频道模块并执行首次同步；同步失败时自动恢复为关闭状态。

真实运行前应先执行第 11 个入口。首次换电脑时，先暂停系统计划任务、升级程序并完成只读检查，再使用第15个入口完成一次安全启用与首次同步；核对没有重复记录后，用第10个入口安装或更新统一自动任务。第15个入口成功后不需要重复运行。
