# YouTube → Lark Dashboard V2 使用说明

本项目会读取 YouTube 频道和 Analytics 数据，并同步到 Lark Base 的三张表。

本文件是已经配置完成后的本地操作手册。从 Google Cloud 开启 YouTube API、创建 OAuth 客户端、配置 Lark/飞书应用与三张表，到 GitHub 安全发布的完整教程，请阅读项目根目录的 `README.md`。

项目目录可以整体复制到其他 Windows 电脑。运行路径、Python 路径和日志路径均不需要手工写死。

> 安全提醒：`data/config.json`、`data/client_secret.json` 和 `data/token.json` 包含账号配置或授权信息，不要上传到公开网盘、公开 Git 仓库或发给无关人员。

## 二、当前电脑上的试用流程

按以下顺序操作：

1. 双击 `run_current.bat`。窗口会实时显示进度，结束后等待按键，不会自动关闭。
2. 打开 `logs/current.log`，确认最后出现 `CURRENT 更新完成`，并且退出码为 `0`。
3. 双击 `run_daily.bat`。窗口会实时显示进度；daily 检查全部视频，通常比 current 更久。
4. 打开 `logs/daily.log`，确认最后出现 `DAILY 更新完成`，并且退出码为 `0`。
5. 确认 Lark 三张表更新正常后，双击 `install_tasks.bat` 安装定时任务。

默认计划：

```text
current：每 15 分钟运行一次
daily：每天 18:00 运行一次
```

时间来自 `data/config.json` 的 `update` 配置。需要调整时，建议重新运行 `setup.bat`，不需要修改 Python 源码。

## 三、迁移到另一台电脑——使用同一运营账号

1. 把整个 `YouTube-Feishu-Dashboard` 文件夹复制到新电脑。
2. 应保留 `data` 文件夹中的三个文件，这样可以继续使用相同的 Lark 和 YouTube 账号。
3. `.venv` 是以点开头的文件夹，不是必须随项目提供的文件。源文件夹中看不到它是正常的；新电脑运行 `install.bat` 后会自动创建。
4. 双击 `install.bat`。如果电脑没有 Python，安装器会优先通过 WinGet 自动安装 Python 3.11；如果 WinGet 不可用，会从 python.org 下载并验证官方安装包后安装。
5. 安装器会创建这台电脑专用的 `.venv` 并安装项目依赖。如果源电脑恰好已有 `.venv`，可以不复制；即使误复制，安装器也会检测并重建。
6. 初始化程序显示现有配置时，直接按回车即可保留原值。
7. 当程序询问是否更换 YouTube 运营账号时，选择 `N`。
8. 安装完成后双击 `doctor.bat`。不要使用系统命令 `python doctor.py`，否则可能绕过项目 `.venv`。

9. Doctor 全部通过后，分别测试 `run_current.bat` 和 `run_daily.bat`。
10. 最后运行 `install_tasks.bat` 安装新电脑的定时任务。

> Windows 定时任务会保存当时的项目路径。因此项目移动位置后，必须重新运行一次 `install_tasks.bat`，它会更新任务路径。

## 四、更换 YouTube 运营账号

1. 双击 `setup.bat`。
2. 不需要修改的 Lark 配置直接按回车保留。
3. 当程序询问是否更换 YouTube 运营账号并重新授权时，选择 `Y`。
4. 浏览器打开后，登录需要同步的新 YouTube 运营账号。
5. 同意 YouTube 只读和 Analytics 授权。
6. 新授权会保存到 `data/token.json`。
7. 双击 `doctor.bat`，确认显示的新频道名称正确。
8. Doctor 全部通过后，再运行 current、daily 和定时任务安装。

也可以直接双击 `auth_youtube.bat` 重新授权。

> 在确认新账号和新配置之前，不要运行 current 或 daily，否则数据仍可能写入原来的 Lark Base。

## 五、更换 Lark App、Base 或三张表

双击 `setup.bat`，根据提示填写：

```text
Lark App ID
Lark App Secret
Lark Base Token
视频主表 Table ID
视频历史表 Table ID
频道历史表 Table ID
```

配置保存后，先双击 `doctor.bat`。

Doctor 会分别检查：

- Lark App ID 和 App Secret 是否可以获取访问令牌；
- Base Token 是否正确；
- 视频主表是否可以访问；
- 视频历史表是否可以访问；
- 频道历史表是否可以访问。

三张表全部通过后再运行同步。

## 六、代理和更新时间调整

双击 `setup.bat` 可以调整：

```text
是否使用代理
代理地址
代理端口
Analytics 回查天数
current 更新间隔
daily 每日运行时间
```

当前默认值：

```text
代理地址：127.0.0.1
代理端口：10808
Analytics 回查：最近 7 天
current：每 15 分钟
daily：每天 18:00
```

如果启用了代理，运行同步和 Doctor 前需要确保代理软件已经启动，而且配置的端口可以连接。

修改定时参数后，要重新运行 `install_tasks.bat`，Windows 任务才会使用新时间。

## 七、Doctor 检查说明

双击 `doctor.bat`。它会固定使用项目自己的 `.venv`，避免误用系统 Python。

Doctor 会进行只读检查，不会更新 Lark 表格，检查内容包括：

- Python 版本；
- Python 依赖；
- `data/config.json` 格式和必填项；
- OAuth 客户端文件；
- YouTube token 和授权范围；
- OAuth 客户端与 token 是否匹配；
- 代理端口；
- Lark App 连接；
- Lark Base 三张表；
- YouTube Data API；
- YouTube Analytics API。

正常结果应为：

```text
检查完成：通过 13，失败 0
环境可用，可以运行 current/daily。
```

## 八、手工运行命令

如果需要在命令行运行，请明确使用项目 Python：

```text
.venv\Scripts\python.exe youtube_lark.py current
.venv\Scripts\python.exe youtube_lark.py daily
```

两种模式的作用：

- `current`：读取频道当前数据和全部视频当前数据，更新视频主表和当天频道快照。
- `daily`：回查最近几天的 YouTube Analytics 日数据，更新视频历史表和频道历史表。

两种模式都使用唯一键更新已有记录。正常重复运行不会因为同一个 Video ID 或同一个日期产生重复数据。

## 九、各文件用途

| 文件 | 用途 |
|---|---|
| `data/config.json` | 本机真实配置，包含 Lark、YouTube 文件路径、代理和更新时间 |
| `data/client_secret.json` | Google Cloud 下载的 OAuth 客户端配置 |
| `data/token.json` | 当前 YouTube 运营账号的 OAuth 授权 |
| `config.example.json` | 不含真实敏感信息的配置示例，可用于制作空白副本 |
| `app_config.py` | 统一读取、校验配置，并处理相对路径 |
| `youtube_lark.py` | 执行 current 和 daily 同步的主程序 |
| `setup.py` | 交互式初始化、配置调整和旧版迁移逻辑 |
| `setup.bat` | 双击启动初始化程序 |
| `auth_youtube.py` | 单独重新授权或切换 YouTube 运营账号 |
| `auth_youtube.bat` | 使用项目 `.venv` 启动 YouTube 授权 |
| `doctor.py` | 检查安装、配置、代理、Lark 和 YouTube API |
| `doctor.bat` | 使用项目 `.venv` 启动 Doctor，避免误用系统 Python |
| `requirements.txt` | Python 依赖清单 |
| `install.bat` | 双击启动完整安装流程；不依赖系统 PATH 寻找 Windows 工具 |
| `install.ps1` | 检测或自动安装 Python、重建 `.venv`、安装依赖并启动初始化 |
| `run_current.bat` | 手工运行时显示 current 进度；定时运行时保持静默 |
| `run_daily.bat` | 手工运行时显示 daily 进度；定时运行时保持静默 |
| `run_sync.py` | 将同步进度同时输出到窗口和 UTF-8 日志，并记录最终退出码 |
| `install_tasks.py` | 生成 Windows 定时任务的底层程序 |
| `install_tasks.bat` | 双击安装或更新 Windows 定时任务 |
| `归档` | 保存 V1 旧脚本和迁移前的旧配置文件 |

## 十、常见问题

### 1. Doctor 提示代理不可连接

检查代理软件是否启动，以及 `setup.bat` 中填写的地址和端口是否正确。如果这台电脑不需要代理，可以在 setup 中关闭代理。

### 2. Doctor 提示 OAuth token 失败

双击 `auth_youtube.bat`。

重新登录正确的 YouTube 运营账号并授权。

### 3. Doctor 提示 Lark 表不可访问

检查对应的 Base Token、Table ID，以及 Lark 自建应用是否已经获得 Base 访问权限。修改后重新运行 Doctor。

### 4. 双击 BAT 没有看到结果

手工双击 BAT 时会实时显示进度并在结束后等待按键，同时写入：

```text
logs/current.log
logs/daily.log
```

定时任务运行时不会打开交互窗口，只写日志。重点查看日志末尾的 `END ... exit=0`。非零退出码表示运行失败，失败原因通常在它前面的几行。

### 5. 定时任务没有运行

检查：

- 项目是否移动过位置；
- Python 本地环境是否仍存在；
- Windows 任务计划程序中任务是否启用；
- 代理软件在任务运行时是否已经启动；
- `logs` 中是否产生了新的运行记录。

项目移动后，重新运行 `install_tasks.bat` 更新任务即可。

### 6. 新电脑提示没有安装 Python

请确认复制的是包含 `install.ps1` 的最新项目文件夹，然后重新双击 `install.bat`。安装器会自动尝试：

```text
WinGet 安装 Python 3.11
        ↓ 如果 WinGet 不可用或安装失败
从 python.org 下载官方 Python 3.11.9 安装包
        ↓
验证 Python Software Foundation 数字签名
        ↓
安装并创建项目 .venv
```

如果两种自动方式都失败，通常是新电脑无法访问 WinGet/python.org，或被公司安全策略阻止。此时请手工从下面的官方页面安装 Python 3.11，然后重新运行 `install.bat`：

```text
https://www.python.org/downloads/release/python-3119/
```

截图中出现 `'chcp' 不是内部或外部命令`，说明新电脑的系统 PATH 不完整。最新版 BAT 已改用 Windows 系统工具的绝对路径，并在当前运行会话中补回 System32，不需要为了本项目手工修改全局 PATH。

### 7. Doctor 出现 `No module named 'google'`

这通常不是配置问题，而是执行了系统命令 `python doctor.py`，从而绕过了项目 `.venv`。请改为：

```text
双击 doctor.bat
```

新版 Doctor 即使被错误的 Python 启动，也会显示缺少哪些依赖并提示使用 `doctor.bat`，不会再直接抛出程序堆栈。

### 8. current/daily 出现 `PROXY_TYPE_HTTP` 错误

这表示项目环境缺少代理模块 `PySocks`。新版 `requirements.txt` 已包含它。重新双击 `install.bat`，安装器会保留现有配置并补齐依赖；然后依次测试：

```text
doctor.bat
run_current.bat
run_daily.bat
```

## 十一、安全与备份

- 不要公开 `data/config.json`、`data/client_secret.json`、`data/token.json`。
- `.gitignore` 已默认排除上述真实配置及日志。
- `config.example.json` 可以公开或复制，它不包含真实账号信息。
- 更换配置前，可以备份整个 `data` 文件夹。
- V1 文件保存在 `归档/V1_迁移备份_20260828_152352`，需要回看旧版本时从这里查找。
- 不要在没有确认 Base Token 和三张 Table ID 的情况下运行同步。

## 十二、推荐操作顺序

以后遇到迁移、换账号或长时间未使用时，统一按照下面的顺序：

```text
install.bat 或 setup.bat
        ↓
doctor.bat
        ↓
run_current.bat
        ↓
run_daily.bat
        ↓
install_tasks.bat
```

只要 Doctor 全部通过，并且两个日志最后都是 `exit=0`，就可以让定时任务长期自动运行。
